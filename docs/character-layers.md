# Разбор персонажа на слои

Как из готовых картинок персонажа получить **сменные слои** — тело, волосы,
черты лица, одежду — и собирать из них новые образы, не генерируя каждый
раз заново.

Дополняет [`character-factory.md`](character-factory.md) (там — как получить
сами картинки) и [`face-compositor.md`](face-compositor.md) (спецификация
слоёв лица).

---

## Главный принцип: дифф пары

Всё держится на одном приёме. Если есть **два кадра одного персонажа,
отличающиеся ровно одним элементом**, то разница между ними и есть этот
элемент:

```
кадр с волосами  −  кадр лысый        =  слой волос
кадр с бровями   −  кадр без бровей   =  слой бровей
кадр одетый      −  кадр без одежды   =  слой одежды
```

Никакого распознавания «что на картинке» не требуется — только вычитание.
Отсюда и все ограничения метода: без пары он не работает вовсе.

**Качество диффа определяется тем, насколько точно совпадают кадры.**
Проверено на практике:

| источник пары | совпадение | результат |
|---|---|---|
| правка одного кадра («убери волосы, остальное не трогай») | ±2–4 px | чистый слой без подбора порогов |
| две независимые генерации в одинаковой позе | ~86–88% | кайма по контуру, нужен `defringe` |
| две генерации в разных позах | ~66% | мусор, метод неприменим |

Практический вывод: просить у генератора **правку конкретного кадра**, а не
новую картинку «в такой же позе».

## 1. Волосы — `hair_mask.py`

```bash
python3 scripts/hair_mask.py build bald.png haired.png -o mask.png --downscale 3
python3 scripts/hair_mask.py apply recolored.png original.png mask.png -o fixed.png
```

`build` строит геометрическую маску волос из пары лысый/волосатый.
`apply` возвращает пикселям под маской исходный цвет — это нужно, когда
палитровая перекраска (`skin_tone_adjust.py`) залезла в волосы: она работает
по индексу палитры и слепа к положению, а волосы — задача позиционная.

**Зачем это понадобилось:** у Kat волосы нарисованы почти той же тёплой
коричневой гаммой, что и тени на коже, размазанной по 11+ записям палитры.
Никакой список исключений по цвету их не разделял — потребовалась геометрия.
На тесте с фиолетовой кожей утечка в волосы упала с 383 пикселей до нуля.

## 2. Черты лица — `face_layer_extract.py` и попарный дифф

Слои `brows / eyes / nose / lips` получены диффом пар «с чертой / без черты».
Лежат в `templates/face/`, собираются через
`characters/kat/face-assemble.json` + `compose.py`.

Что выяснилось по ходу:

- **Порог подбирается под каждую черту.** Нос — тень, а не цвет: его
  расстояние до квантованного соседа всего ~20, тогда как у глаз ~130.
  Единый порог либо теряет нос, либо тащит мусор.
- **Отдельного слоя бровей может не быть.** В одной серии кадров то, что
  выглядело бровью, оказалось верхней линией века и удалялось вместе с
  глазом. В другой серии брови были самостоятельными. Смотреть надо на
  конкретный арт, а не предполагать.
- **Границы вырезки надо проверять глазами.** Первая версия слоя глаз
  обрезала нижнее веко и внешний угол дальнего глаза — заметно только при
  сборке.

## 3. Одежда — `extract_clothing.py`

```bash
python3 scripts/extract_clothing.py base.png clothed.png -o garment.png \
    --threshold 40 --min-blob 2000
```

`base.png` — тело без этой одежды. Всё, что изменилось, считается одеждой.

### База решает больше, чем любые параметры

**Базу нужно брать телесного цвета, а не в тёмном белье.** Если на базе
чёрный лифчик, то чёрная одежда поверх него не даёт никакой разницы —
дифф эту область просто не видит, и в слое остаётся дыра. Именно это
вырывало кусок из чёрного топа и породило бенчмарк 54.9%.

Замер на одном и том же источнике (чёрный топ + шорты):

| база | извлечено |
|---|---|
| `kat_06` — чёрное бельё | 136 728 px, топ разорван поперёк груди |
| `kat_15` — телесный боди | **169 390 px (+24%)**, топ цельный |

Недостающие 32 тысячи пикселей — ровно тот вырванный кусок. Канонической
базой для позы «руки вниз» считать `kat_15`.

В отличие от пар для волос и лица, независимо сгенерированные кадры нарядов
«плывут» по масштабу и положению — в наборе Kat разброс роста до ~70 px, и
даже размеры холста разные (1023×1537, 1027×1532, 1029×1528 вместо
1024×1536). Поэтому скрипт сначала нормализует по bounding box, иначе дифф
возвращает силуэт персонажа вместо одежды.

### Осколки после чистки — второй проход `largest_blobs`

`defringe` не добавляет мусор, он его удаляет — но, вырезая пиксели, может
**раздробить** один блок, уже прошедший фильтр `--min-blob` при вырезке, на
несколько несвязных обрывков, каждый из которых поодиночке меньше порога и
раньше просто не мог возникнуть. Найдено на шортах `kat_16`: тонкая тёмная
линия контура ноги (не кожа — фильтр по оттенку её не ловит) шла от колена
до пальцев одним блоком >2000 px, прошла вырезку, а `defringe` вычистил
середину и оставил ~15 несвязных огрызков по 89–265 px — в сумме незаметно
на глаз (в общем счётчике пикселей), но заметно на теле в другой позе, где
контур ноги уже не совпадает.

Затронуло не только новый наряд: пересборка всего гардероба со вторым
проходом `largest_blobs` **после** `defringe` (а не только до) вычистила
6627 px у футболки с шортами, 4495 px у белого платья, 6126 px у джинсов —
предметы считались чистыми, обрывки просто были не видны без проверки.
`defringe.py` теперь гоняет `largest_blobs` автоматически после обеих
своих правил (`--no-refilter`, чтобы отключить); `build_wardrobe.py` делает
то же самое для своего внутреннего вызова.

### Чистка каймы — `defringe.py`

```bash
python3 scripts/defringe.py garment.png -o clean.png --base base.png
```

Мусор по краям — не случайный шум, а **систематическая лента контура тела**
от неидеального совмещения. Раз систематический — лечится правилом, без
всякого обучения:

- **тонкие структуры цвета кожи** (не переживают морфологическое открытие) —
  основное правило, снимает ~23 500 px на джинсах;
- **полоса вдоль силуэта базы** — дополнительное, снимает ~8 500 px.

Тёмную обводку персонажа правила не трогают намеренно: убирать тонкие
тёмные структуры значит съесть и собственную обводку одежды.

⚠️ **На тёмной одежде `defringe` вреден.** На чёрном комплекте Kat он выел
40 896 px, включая куски самой одежды (против 23 528 на джинсах). Для
тёмных вещей — либо отключать, либо см. §5.

### Пакетная сборка — `build_wardrobe.py`

```bash
python3 scripts/build_wardrobe.py base.png outfit1.png outfit2.png ... \
    --out-dir templates/wardrobe/<character>
```

Прогоняет `extract_clothing` → `defringe` по всей папке кадров разом и
**пропускает `defringe` на тёмных предметах** (порог `--dark-threshold`).

Критерий «тёмности» — **доля тёмных пикселей**, а не средняя яркость.
Первая версия считала среднее и промахнулась ровно на том случае, ради
которого писалась: сырой слой несёт светлую кайму кожи, и она задирает
среднее настолько, что чёрный топ не отличить от синих джинсов:

| предмет | среднее | медиана | доля тёмных |
|---|---|---|---|
| чёрный топ+шорты | 0.32 | 0.15 | **70%** |
| готик-юбка | 0.27 | 0.12 | **77%** |
| джинсы | 0.52 | 0.48 | 15% |
| белое платье | 0.88 | 0.93 | 3% |

По среднему тёмное и светлое перекрываются, по доле тёмных — разделяются
с большим запасом.

## 4. Надевание, в том числе на другую позу — `fit_garment.py`

```bash
python3 scripts/fit_garment.py body.png garment.png -o dressed.png \
    --source-body base_the_garment_was_cut_from.png
```

Одежда, вырезанная из одной позы, **садится и на другую позу рук**. Это
неочевидно, поэтому вот замеры (якорь по ступням и центру ног — нормировать
по габариту нельзя, поднятые руки поднимают верх рамки и незаметно
масштабируют тело):

| зона (вверх от ступней) | руки вниз ↔ руки **вверх** | контроль: вниз ↔ вниз |
|---|---|---|
| ноги 0–30% | **90.0%** | 80.9% |
| бёдра 30–45% | 85.7% | 86.7% |
| торс 45–70% | 63.9% | 89.3% |
| плечи+голова 70–100% | 56.0% | 72.3% |

Ноги при разных позах рук совпадают **лучше**, чем у двух кадров с одинаковой
позой. Низкая цифра по торсу — артефакт метрики, а не реальности: IoU
силуэта засчитывает опущенные руки как часть полосы торса, то есть штрафует
за движение рук, а не за несовпадение торса. На практике переносится **весь
комплект целиком**, включая верх. Реально привязаны к позе рук только вещи,
облегающие руки — рукава, куртки.

Главный артефакт переноса — **призраки конечностей**: слой одежды несёт
тёмную обводку оттуда, где были руки в исходном кадре. Снимается маской по
силуэту тела-приёмника (одежды не бывает там, где нет тела) — 5.3 тыс. px на
джинсах, 7.2 тыс. на платье.

Второй артефакт, увиденный на топе с вырезом (`kat_16`, вырезан в позе
«руки вверх», надет на тело «руки вниз»): в вырезе проступил ромбик голой
кожи телесного цвета базы. Причина — при поднятых руках грудная клетка
приподнята и ткань топа облегает её иначе, верхняя кромка выреза сидит на
пару пикселей выше, чем при опущенных руках. Это не призрак-обводка (тот
уже снят маской), а честное несовпадение кроя в позе-чувствительной зоне.
Для плотно прилегающих верхов с вырезом на груди тоже стоит проверять
глазами, даже если перенос низа и общего силуэта явно чистый.

`fit_garment.py` умеет ручную поправку сверх авто-подгонки по ступням —
`--nudge-x` / `--nudge-y`. Перебор сетки 2D-сдвигов (`--nudge-x` ±20,
`--nudge-y` −24…−4) показал: сдвиг по **X не помогает вовсе** (лучшая
находка с X≠0 хуже, чем при X=0, и отрывает лямку с другого плеча), а
чистый сдвиг **вверх на −24 px** даёт лучший результат из всех проверенных
— «кожа» в зоне выреза падает с 18 116 до 15 328 px (**−15%**), без новых
дыр по бокам. Полностью не закрывается — это подтверждает, что причина не
в положении слоя, а в форме выреза, — но −24 px по Y ощутимо лучше, чем
ничего, и это разумная ручная поправка для конкретно этого наряда.

**Поворот (`--rotate`) тоже проверен и не годится.** По той же метрике
поворот на −4° вокруг центра слоя даёт формально ещё меньше «кожи» в
вырезе (14 361 px, лучше любого сдвига), но визуально это хуже: тело
персонажа не наклонено, наклонена только грудная клетка внутри позы, а
поворот — жёсткое преобразование всего слоя. Верх «чинится», а низ —
шорты — раскашивается на бёдрах, что заметно сильнее и хуже, чем
исходный маленький зазор в вырезе. Урок: когда несовпадение — это разница
**формы** (а не позиции и не угла) конкретного участка, любое жёсткое
преобразование всего слоя (сдвиг, поворот) чинит один участок за счёт
другого. Флаг оставлен в инструменте — он законный для случаев, когда
рассинхрон именно в повороте, просто не для этого случая.

**Рабочее решение — не чинить верх, а не переносить его вовсе.** Раз
проблема живёт только в области груди (зона с самым низким кросс-позным
совпадением, 63.9% в таблице выше), а низ (ноги/бёдра, 90.0%/85.7%)
переносится без единого артефакта — слой можно разрезать на верх и низ по
голому пояснице между ними и переносить их раздельно. Из `kat_16` вырезаны
только шорты (`kat_16_acid_shorts_only.png`, обрезка по y ≥ 570 в
координатах исходного слоя) и надеты на тело «руки вниз» без единой
поправки — зазора нет вообще, потому что зона бёдер и так хорошо
совпадает между позами. Топ для этой позы либо берётся из вещи, уже
вырезанной в позе «руки вниз», либо остаётся только для позы «руки
вверх», для которой был снят изначально.

## 5. Кислотный трюк и перекраска — `recolor_garment.py`

Качество вырезки определяется **контрастом**, а не сложностью одежды.
Измерено: чёрный комплект Kat дал IoU всего **54.9%** против настоящего
рендера того же наряда в той же позе, тогда как белое платье и синие джинсы
вырезались чисто.

Отсюда приём: генерировать одежду в **кислотном цвете** (максимальный
контраст и с кожей, и с тёмной обводкой), вырезать её начисто, а нужный цвет
задавать программно:

```bash
python3 scripts/recolor_garment.py garment.png -o red.png --color '#c0202c'
python3 scripts/recolor_garment.py garment.png -o dark.png --color '#1a1a1a' \
    --v-lo 0.06 --v-hi 0.30
```

Светотень сохраняется, потому что переносится **диапазон яркости самой
ткани**, а не плоская заливка: складки, рюши, швы остаются. Оговорка: у
чистого чёрного нет тонального запаса, поэтому «чёрный» пресет даёт
угольный — если дожать до настоящего чёрного, складки исчезнут.

Побочная выгода: из одного вырезанного предмета получается **сколько угодно
цветовых вариантов бесплатно** — нет смысла генерировать платье пять раз в
пяти цветах.

**Проверено на второй паре** (`kat_16`/`kat_17`, спортивный костюм в
кислотных салатовом/розовом, руки вверх): извлечение вышло чище всех
предыдущих — всего 5% тёмных пикселей, `defringe` снял 12 608 px без риска
съесть ткань (в отличие от тёмной одежды, где он и включаться не должен;
после починки второго прохода `largest_blobs` — см. ниже — итог 94 154 px
вместо 97 620). Перекраска в чёрный и тёмно-синий подтвердила — складки,
шов на боку шорт и окантовка топа остаются видны в обоих цветах.

## 6. Проверка качества

Единственный способ узнать, насколько хорош перенос — иметь **тот же наряд,
реально отрисованный в целевой позе**, и сравнить с ним. Без этого легко
обмануться: платье и джинсы выглядели отлично именно потому, что светлые, и
по ним складывалось ложное впечатление, что метод работает везде.

Сравнение делается по маске одежды (IoU + сколько лишнего / сколько
потеряно). Текущий бенчмарк — 54.9% на тёмном комплекте, от него и надо
улучшать.

### Зазор на обтягивающем вырезе — предел жёсткой и нежёсткой деформации

На топе с глубоким вырезом (`kat_16`, перенесённом с позы «руки вверх» на
«руки вниз») в вырезе виден ромбик кожи — грудная клетка ниже и шире при
опущенных руках, а плотно прилегающая ткань топа этого не повторяет.
Перепробовано по нарастающей:

| приём | зазор (px кожи в окне) | побочный эффект |
|---|---|---|
| без поправки | 18 116 | — |
| сдвиг по Y (`--nudge-y -24`) | 15 328 (−15%) | нет |
| сдвиг по X+Y (сетка 5×5) | 16 080 (−11%) | новый зазор у другой лямки |
| поворот на −4° (`--rotate`) | 14 361 (−21%) | шорты кривятся на бёдрах |
| локальный нежёсткий warp по столбцам | 14 727 (−19%) | залом в кромке на стыке зон |

Ни один вариант не закрывает зазор полностью — потому что нужных пикселей
(грудь именно в этой форме) нет ни в одном референсе, взяться им неоткуда.
Каждый следующий приём давал всё меньший прирост ценой всё более заметного
побочного артефакта — падающая отдача, дальше жать чистой геометрией
невыгодно.

**Практический вывод: обтягивающее — только под свою позу, свободное —
переносится куда угодно.** Из всего гардероба проблема вылезла ровно на
одном типе вещи — плотно облегающем топе с вырезом. Свободный крой (футболка,
топ на бретелях без плотного прилегания, платье, куртка) везде переносился
чисто между позами без единого артефакта — у него есть запас драпировки,
который прощает несовпадение формы грудной клетки. Значит для гардероба,
рассчитанного на перенос между позами, стоит по возможности предпочитать
свободный крой; для обтягивающих вещей — три пути: снимать сразу в нужной
позе, закладывать ручную доводку через `learn_from_corrections.py`, либо (для
однотонной обтяжки без рисунка) не переносить форму вообще — см. §7,
`skin_to_fabric.py`.

## 7. Обтяжка как материал, не как спрайт — `skin_to_fabric.py`

Из зазора на вырезе (§4) следует более общий вывод: у обтягивающей одежды
почти нет собственного силуэта — её форма и есть форма тела. Значит
переносить её как отдельный вырезанный объект в принципе неверная модель:
сколько ни двигай и ни гни готовую картинку, у неё нет пикселей на случай
«тело здесь чуть другой формы». А у свободной одежды есть — драпировка
прощает несовпадение.

Выход — не переносить форму вообще. Маска покрытия (та же вырезка через
`extract_clothing.py` на кислотной обтягивающей вещи, что и всегда) даёт
только **где** есть одежда, не **какого она цвета**. Дальше берём не
пиксели вырезанного слоя, а пиксели **самого тела-приёмника** под этой
маской — и перекрашиваем уже их через `recolor_garment.recolor()`.
Результат в буквальном смысле не может не сесть по фигуре: он и есть эта
фигура, просто перекрашенная.

```bash
python3 scripts/skin_to_fabric.py body.png coverage_mask.png -o dressed.png \
    --source-body body_the_mask_was_cut_against.png --color '#2c3e6b'
```

Проверено на шортах `kat_16`: маска, снятая с позы «руки вверх», надета на
тело «руки вниз» — пояс и посадка на бёдрах повторяют настоящий крой (форма
взята из маски), блики на колене и тень под коленом настоящие (взяты из
пикселей тела в этой самой позе). Зазора, который мучил обтягивающий топ, тут
в принципе не может быть — форма никогда никуда не переносилась.

По пути всплыл тот же баг нормализации, что и в `recolor_garment.py`, только
острее: у кожи реальный разброс яркости узкий (медиана v≈0.97), и старая
версия на истинном min/max сжимала всю светотень в невидимую полоску —
результат выглядел плоской заливкой без единой складки. Чинится тем же
процентильным клиппингом (2/98), уже внесённым в `recolor_garment.py`.

Ограничение метода честно: раз это перекраска кожи, а не одежда, деталей
типа шва или принта на ткани здесь нет и взяться неоткуда — только
светотень тела. Для однотонной обтяжки (леггинсы, боди, велосипедки) этого
достаточно; для вещи с рисунком — нет.

## 8. Обучение на ручных правках — `learn_from_corrections.py`

Ручная правка ничему не учит систему, если её не сохранить машиночитаемо.

```bash
# после ручной чистки auto.png -> fixed.png
python3 scripts/learn_from_corrections.py record --auto auto.png --fixed fixed.png \
    --name kat_jeans --source-base base.png --source-clothed clothed.png
python3 scripts/learn_from_corrections.py tune --name kat_jeans
python3 scripts/learn_from_corrections.py report
```

- `record` складывает пару (что выдал скрипт / что ты утвердил) в
  `characters/_corrections/` и считает, сколько пикселей человек убрал и
  вернул;
- `tune` перебирает `threshold` / `min_blob` / `thin_radius` и находит
  настройки, максимально воспроизводящие твою версию — **работает с одного
  примера**;
- `report` показывает накопленный корпус и говорит, когда его хватит для
  обучаемого классификатора (ориентир — 10–20 правок).

Почему подбор параметров, а не нейросеть: работает от одного примера, считает
секунды, и результат — читаемое число, которое можно перепроверить, а не
непрозрачные веса. Классификатор осмысленен позже — и именно он позволит
отделять одежду **на одиночной картинке, без пары**, чего дифф не умеет
принципиально.

---

## Что метод не умеет

- **Работать без пары.** Одна произвольная картинка → вырезать одежду
  нельзя: нечего вычитать.
- **Додумывать невидимое.** Что под одеждой, как выглядит спина — в пикселях
  этого нет.
- **Деформировать ткань под новую позу.** Одежда переносится как есть; вещи,
  облегающие руки или грудь, требуют совпадения позы (см. §4) — ни сдвиг,
  ни поворот, ни локальный warp не заменяют недостающие пиксели.
- **Называть слои по смыслу.** «Это юбка, а это шорты» угадывается только по
  высоте в кадре, с ошибками.
